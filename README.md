# Система управления БД

Учебная система управления базой данных с двумя взаимозаменяемыми бэкендами хранения
и текстовым пользовательским интерфейсом. 

## Структура проекта

```
.
├── src/
│   ├── __init__.py
│   └── db/
│       ├── __init__.py
│       ├── __main__.py              # точка входа: python -m src.db
│       ├── tui.py                   # текстовый интерфейс
│       └── backend/
│           ├── __init__.py
│           ├── errors.py            # все исключения проекта
│           ├── table.py             # класс Table (валидация и CRUD над записями)
│           ├── database.py          # абстрактный Database (общий API)
│           ├── memory.py            # MemoryDatabase — хранение в ОЗУ
│           └── file.py              # FileDatabase  — хранение в JSON-файлах
│
├── tests/
│   ├── __init__.py
│   ├── test_memory.py               # тесты Table и MemoryDatabase
│   └── test_file.py                 # тесты FileDatabase + persistence
│
├── data/                            # создаётся автоматически FileDatabase
│   └── *.json                       # по одному файлу на таблицу
│
├── README.md
└── .gitignore
```


## Функциональность

### Работа с таблицами

- Создание таблицы с заданным набором колонок (первая колонка обязательно `id`).
- Удаление таблицы.
- Проверка существования таблицы.
- Получение списка всех таблиц.

### Работа с записями

- Вставка записи с проверкой структуры и уникальности `id`.
- Выборка всех записей или с фильтрами по точному совпадению значений.
- Обновление записи по `id` (любого набора полей, кроме самого `id`).
- Удаление записи по `id`.
- Сортировка записей по любому полю по возрастанию или убыванию.

### Два бэкенда хранения

- **In-memory** (`MemoryDatabase`) — данные живут в оперативной памяти и теряются
  при выходе из программы. Подходит для тестов и временной работы.
- **File** (`FileDatabase`) — каждая таблица сохраняется в отдельный JSON-файл
  в каталоге `data/`. Данные переживают перезапуск программы и подгружаются
  автоматически при следующем старте.

Оба бэкенда реализуют один и тот же интерфейс `Database`, поэтому TUI и любой
пользовательский код работают с ними одинаково.

### Текстовый интерфейс

При запуске программа спрашивает, какой бэкенд использовать, и далее предлагает
меню со всеми операциями:

1. Показать список таблиц.
2. Показать содержимое таблицы.
3. Создать таблицу.
4. Вставить запись.
5. Выбрать записи (с опциональными фильтрами).
6. Обновить запись.
7. Удалить запись.
8. Отсортировать записи.
9. Удалить таблицу.
0. Выход.

### Обработка ошибок

Все ошибки наследуются от `DatabaseError` и перехватываются в TUI — программа
никогда не падает со стектрейсом из-за некорректного ввода:

- `TableNotFoundError` — таблица не найдена.
- `TableAlreadyExistsError` — таблица уже существует.
- `DuplicateIDError` — попытка вставить запись с уже существующим `id`.
- `RecordNotFoundError` — запись с указанным `id` не найдена.
- `ColumnNotFoundError` — обращение к несуществующей колонке.
- `InvalidDataError` — некорректные данные (неверная структура колонок,
  неподходящий тип `id`, несравнимые типы при сортировке).
- `InvalidStorageDataError` — повреждённый JSON-файл (только для `FileDatabase`).

### Формат хранения на диске

Каждая таблица — отдельный файл `data/<имя_таблицы>.json`:

```json
{
  "columns": ["id", "name", "age"],
  "records": [
    {"id": 1, "name": "Alice", "age": 25},
    {"id": 2, "name": "Bob", "age": 30}
  ]
}
```

## Инструкция по запуску

### Требования

- Python 3.10 или новее.
- Сторонние зависимости не нужны — используется только стандартная библиотека.

### Запуск программы

Все команды выполняются **из корня проекта** (каталог, в котором лежат `src/`
и `tests/`).

```bash
python -m src.db
```

При старте программа предложит выбрать бэкенд:

```
==================================================
         ВЫБОР ТИПА БАЗЫ ДАННЫХ
==================================================
1. In-memory (данные не сохраняются между запусками)
2. File (данные сохраняются в каталог data/)
==================================================
Выберите тип БД (1/2):
```

Дальше работа идёт через числовое меню. Для выхода — пункт `0`.

### Запуск тестов

Все тесты:

```bash
python -m unittest discover -s tests -v
```

Отдельные модули:

```bash
python -m unittest tests.test_memory -v
python -m unittest tests.test_file -v
```

Тесты `FileDatabase` используют временные каталоги (`tempfile.TemporaryDirectory`),
поэтому реальные данные в `data/` не затрагиваются.
