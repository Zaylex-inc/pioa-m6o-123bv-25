## Архитектура

### Слой данных — `src/db/backend/memory.py`

- **`Table`** — таблица с фиксированным набором колонок. Первая колонка обязана называться `id` и содержать значения типа `int`. Поддерживает:
  - `insert_record(record)` — вставка с проверкой схемы и уникальности `id`;
  - `select_records(**filters)` — фильтрация по любым полям через kwargs;
  - `update_record(record_id, **updates)` — обновление с fail-fast валидацией ключей;
  - `delete_record(record_id)` — удаление по `id`;
  - `sort_records(field, descending=False)` — сортировка по любому полю в обоих направлениях.

  Все методы, возвращающие записи, отдают глубокие копии — внешний код не может изменить внутреннее состояние таблицы.

- **`Database`** — контейнер для множества именованных таблиц. Делегирует операции в соответствующую `Table` после проверки её существования. Методы: `create_table`, `drop_table`, `get_table`, `has_table`, `get_tables`, плюс делегирующие обёртки `insert_record` / `select_records` / `update_record` / `delete_record` / `sort_records`.

### Слой представления — `src/db/tui.py`

Класс **`TUI`** реализует текстовое меню с пунктами:

1. Показать все таблицы
2. Информация о таблице
3. Создать таблицу
4. Вставить запись
5. Выбрать записи (с фильтрами или без)
6. Обновить запись
7. Удалить запись
8. Сортировать записи (asc / desc)
9. Удалить таблицу
0. Выход

TUI не лезет напрямую во внутренние поля `Table` / `Database` — пользуется публичным API (`get_table`, `has_table`, `get_columns`, `get_record_count` и т.д.). Все исключения слоя данных перехватываются и превращаются в понятные сообщения для пользователя. Меню реализовано через словарь `actions` для расширяемости.

Вспомогательный метод `_try_convert` единообразно приводит пользовательский ввод к `int`, `float` или оставляет строкой — корректно работает с отрицательными числами и дробями.

### Иерархия исключений — `src/db/backend/errors.py`

```
DatabaseError                  # базовый класс — ловится одним except для любой ошибки слоя данных
├── TableNotFoundError         # таблица не найдена
├── TableAlreadyExistsError    # таблица с таким именем уже существует
├── DuplicateIDError           # ID уже существует в таблице
├── RecordNotFoundError        # запись не найдена
├── InvalidColumnError         # колонка не определена в структуре таблицы
├── InvalidRecordError         # запись не соответствует структуре таблицы
├── InvalidIDTypeError         # тип id должен быть int
└── InvalidColumnsError        # некорректная структура колонок при создании
```

## Тестирование

Тесты написаны на стандартном модуле `unittest`. Для табличных сценариев используется `subTest` — это позволяет видеть, на каком именно наборе данных тест упал, не прерывая остальные кейсы. Для тестирования TUI применяется `unittest.mock.patch`, который подменяет `input()` и `print()` — это даёт возможность проверять интерфейс без реального участия пользователя.

```bash
# Все тесты с подробным выводом
python -m unittest discover -s tests -p "test_*.py" -v

# Только модель данных
python -m unittest tests.test_memory -v

# Только TUI
python -m unittest tests.test_tui -v
```

Всего тестов: **93** (53 на `memory.py` + 40 на `tui.py`).

## Функциональность

### Операции с таблицами
- Создание таблицы с произвольным набором колонок (первая колонка обязана быть `id`, имена колонок уникальны).
- Удаление таблицы.
- Просмотр списка таблиц с количеством записей.
- Детальная информация о таблице — колонки, число записей, пример.

### Операции с записями
- **Вставка**: проверка типа `id` (`int`), наличия всех колонок схемы, отсутствия лишних колонок, отсутствия дубликата `id`.
- **Выборка**: без фильтров возвращает все записи; с фильтрами через kwargs (`select_records("users", age=25, sex="F")`).
- **Обновление**: по `id`, с валидацией ключей **до** мутации (fail-fast — если хоть одно поле невалидно, ни одно значение не изменится).
- **Удаление**: по `id`, возвращает удалённую запись.
- **Сортировка**: по любому полю в порядке возрастания или убывания. Значения `None` уходят в конец независимо от направления. При несравнимых типах в колонке кидается `InvalidRecordError`.

### Защита данных
Все методы, возвращающие записи (`get_records`, `select_records`, `update_record`, `delete_record`, `sort_records`), отдают `deepcopy`. При вставке запись тоже копируется — мутация исходного словаря снаружи не затрагивает БД.

## Принципы разработки

- **TDD-стиль**: для каждой новой возможности сначала пишется тест, затем реализация.
- **Fail-fast валидация**: все проверки выполняются до мутации состояния — при ошибке данные остаются нетронутыми.
- **Иерархия исключений**: один корневой класс `DatabaseError` позволяет ловить любую ошибку слоя данных одним `except`, а специфичные исключения дают точную диагностику.
- **Изоляция слоёв**: TUI работает только через публичный API `Database`, без прямого доступа к `_records` или `_tables`.
- **Защитное копирование**: внешний код не может изменить внутреннее состояние БД.
- **Type hints** на всех публичных методах.
